# 0.2.25 更新说明

未签名测试发布；内核仍为 sing-box 1.14.4。本版按“VPS 没有 IPv6”这一前提修正 IPv6 判定。

## VPS 没有 IPv6 时，之前的判定是错的

- 旧逻辑把配置 TUN 里的 `fdfe:dcba:9876::1/126` 当成“配置支持 IPv6”，于是开启 IPv6、DNS 返回 AAAA。
- 但 TUN 地址只是客户端自己的约定，跟服务器有没有 IPv6 无关。VPS 没有 IPv6 时，这条路径要么连不通，要么在系统未接管 IPv6 时直接泄露手机自己的运营商 IPv6（就是之前截图里的 `240e:`）。
- 你贴的“两台节点”配置正属于这种：节点都是域名、TUN 里带 `fdfe` 地址，因此会被误判为“支持 IPv6”。

## 新判定：只认真正的 IPv6 端点

- 只有配置里出现 **IPv6 DNS 服务器**（例如 `2001:db8::53`）或 **IPv6 节点服务器地址**（例如 `2001:db8::1`）时，才开启 IPv6。
- 只有 TUN 里写 `fdfe:…` 地址、节点全是域名 → 判定为 **无 IPv6**：TUN 内拒绝 IPv6，DNS 强制 `ipv4_only`，浏览器拿不到 AAAA。
- 基础配置继续按 IPv4-only 构建，与你的 VPS 能力一致。

## 影响

- 你现有的“两台节点”配置现在会自动按 IPv4-only 运行，不会再开 AAAA，也就不会再出现之前的 IPv6 泄露。
- 以后换了支持 IPv6 的节点：把节点服务器直接填 IPv6 地址，或在配置里放一个 IPv6 DNS，应用会自动开启 IPv6。

## 真机调试记录（本次）

- Wi-Fi 双栈（`2408:824c:9030:bf40::/64`）下，`vpn-tun` 已配置 IPv6 地址 `fdfe:dcba:9876::1/126`。
- 发 15 个 `ping6` 时 `vpn-tun` 接收计数比空闲基线多约 15 个包，说明**网络稳定时 IPv6 能被收进隧道**；无回包是因为当前配置在 TUN 内拒绝 IPv6。
- 之前的泄露更可能发生在“切换网络后系统未把 VPN 的 IPv6 路由应用到新网络”，这一点要等 USB 调试下切换网络才能最终确认；在此之前 IPv4-only 是最稳的。
