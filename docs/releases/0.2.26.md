# 0.2.26 更新说明

未签名测试发布；内核仍为 sing-box 1.14.4。按你的定义修正 IPv6 语义。

## 语义

- **TUN 里有 IPv6 地址 = 接管 IPv6**：客户端把 IPv6 收进隧道，按路由规则处理（默认走代理），不再因为“服务器可能没有 IPv6”而提前拒绝。
- **IPv6 能不能真正用，取决于 VPS**：VPS 没有 IPv6 时，发往 IPv6 的连接会在代理侧失败；浏览器可能先尝试 IPv6 再回退 IPv4，页面偶尔会慢一点，但流量不会再从物理链路漏出去。

## 本次改动

- 基础配置恢复双栈 TUN：`172.19.0.1/30` + `fdfe:dcba:9876::1/126`。
- IPv6 判定恢复为“TUN 有 IPv6 地址即开启”，同时保留 IPv6 DNS / IPv6 节点地址作为补充依据。
- **防泄漏补强**：检测到 Wi-Fi ↔ 蜂窝切换、且当前配置启用 IPv6 时，主动重建一次 VPN/TUN，让系统在新网络重新安装 IPv6 默认路由。之前的泄露最可能就发生在这一步——旧网络的 VPN 路由没有应用到新网络。
- 重建走已有的恢复流程（有退避与次数上限），不会死循环；IPv4-only 配置不受影响，不会额外重启。

## 真机验证记录

- Wi-Fi 双栈（`2408:824c:9030:bf40::/64`）下，`vpn-tun` 已配置 `fdfe:dcba:9876::1/126`。
- 发 15 个 `ping6`，`vpn-tun` 接收计数比空闲基线多约 15 个包，确认 IPv6 被收进隧道。
- 之前截图中 `240e:` 泄露发生在蜂窝网络，最符合“切网后 IPv6 路由未重建”，本次改动针对这一点。
