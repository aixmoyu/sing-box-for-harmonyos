# 0.2.40 Beta 配置导入与存储兼容修复

0.2.38／0.2.39 Beta 打包时全量替换包名，误改了 HUKS 密钥别名及 AES-GCM 认证前缀。旧版密文无法按新标识读取，界面因此可能显示空列表，保存新配置时也会被旧文件验证阻止。0.2.36 与0.2.39 的实际 HAP 已确认存在此差异。

- 恢复固定的存储标识，与应用包名、普通／Beta 通道名称分离。
- 对已经使用误改 Beta 标识写入的密文，兼容读取该历史“别名＋认证前缀”组合；仍须通过完整 GCM 认证和业务格式校验，不尝试明文降级。
- 读取时不再生成替代密钥；不删除密钥，不清空应用数据。后续成功保存仍经过候选读回、认证、原子提升，失败保留原文件。
- Beta 构建改为只修改明确的包身份字段，增加加密实现逐字节一致校验，避免再次误改协议标识。
- 初始化和导入错误增加持久提示及阶段／系统错误码，不记录订阅链接、节点密码或原始配置。保留0.2.39严格防护和检测功能。

验证：17项存储相关测试通过，其中6项独立AES-GCM兼容测试覆盖旧Beta、误改Beta、双密钥共存、损坏密文拒绝、无密钥读取不生成密钥及分块边界。全量393项：347通过，45项既有失败，1跳过，无新增失败。普通与Beta Release构建通过。

尚未签名安装0.2.40进行真机恢复验证。WebRTC严格开关对照测试因配置读取失败尚未完成；这份修复不作为IPv6泄漏已解决的证明。请同签名覆盖更新，不要卸载或清除应用数据。若系统已删除原密钥，本修复无法凭空恢复密钥。
