# 0.2.27 更新说明

未签名测试发布；内核仍为 sing-box 1.14.4。按你的定义修正 IPv6 处理。

## 现在的语义

- **TUN 接管所有 IPv4 / IPv6 流量**：两个协议族的包都进隧道，不再按“配置里有没有 IPv6”做取舍。
- **命中代理规则的连接统一交给节点**：客户端只负责把流量送到代理，实际走 IPv4 还是 IPv6 由节点侧决定。
- 因此客户端**不再**做两件事：不再插入 `ip_version: 6` 的 reject 规则；不再把 DNS 强制成 `ipv4_only`，AAAA 正常返回。

## 本次改动

- 移除 `TrafficPrivacy` 里的 IPv6 拒绝与 AAAA 抑制逻辑。
- 基础配置保持双栈 TUN：`172.19.0.1/30` + `fdfe:dcba:9876::1/126`。
- 设置页 IPv6 行改为只读说明：“TUN 接管 IPv4 与 IPv6，代理流量交给节点，出口由节点决定”。
- 保留 STUN 走代理、Wi-Fi ↔ 蜂窝切换时重建 VPN（确保新网络重新安装隧道路由）。

## 说明

- 你的 VPS 没有 IPv6 时，发往 IPv6 目的地的连接会在节点侧失败；浏览器可能先尝试 IPv6 再回退 IPv4，页面偶尔慢一点。这是可用性问题，不是泄露——流量仍然进隧道后才交给节点。
- 如果某天发现 IPv6 又直接出现在检测页，先看是否为切网瞬间：那说明系统没有把 IPv6 路由应用到新网络，本次的重建逻辑就是针对这个场景。
