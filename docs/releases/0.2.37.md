# 0.2.37 更新说明

未签名测试发布；内核仍为 sing-box 1.14.4。

## 借鉴 dae 的 WebRTC 防护

dae 的常见防泄露做法是在 **DNS 层直接拒绝 STUN 主机名**（例如 `qname(regex: '^stun\..+') -> reject`），让浏览器根本拿不到 STUN 服务器地址，也就无法生成公网候选地址。参考：
- https://github.com/daeuniverse/dae
- https://github.com/daeuniverse/dae/issues/1068

本版在基础配置的两个分流方式里都加了同样的规则，排在 DNS 规则第一位：

```json
{ "domain_regex": ["^stun\\."], "action": "reject" }
```

## 配合已有机制

- 域名解析阶段：`stun.*` 直接拒绝（REFUSED），浏览器拿不到 STUN IP。
- 若应用使用字面量 IP 或缓存地址：仍会被 TUN 收进隧道，已有的 STUN 嗅探规则会把 UDP STUN 交给代理出站。
- 两种路径都不会让 WebRTC 用物理网络出去；VPS 没有 IPv6/UDP 时表现为打不通，而不是泄露。

## 影响

- 依赖 STUN 的应用（部分语音/视频通话）可能无法建立 P2P，只能走中继或失败；这是防泄露的代价。
- 直连模式、SSID 挂起、分应用排除的应用仍按明确设置直连，不受此规则保护。
