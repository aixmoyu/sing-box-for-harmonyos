# 0.2.21 更新说明

未签名测试发布；内核仍为 sing-box 1.14.4。本次针对“切换网络后很久才有外网”定位并修复。

## 原因

1. **AUTO 组不会在切网时重测**：基础配置的 `proxy` 默认指向 `AUTO`（urltest），组只按 `interval` 重新测速，原值是 **5 分钟**。切网后旧节点往往已经不可用，但 `AUTO` 仍把流量交给它，最长要等 5 分钟才会换节点。
2. **DNS 全部走代理**：`dns.final` 是 `dns-remote`（经 proxy 的 1.1.1.1）。当 `AUTO` 指向的节点失效时，连国内域名也解析不了，表现就是“完全没网”，而不只是海外网站打不开。
3. **切网事件本身有延迟**：系统要等新网络变成 VALIDATED，签名才变化；之后 200ms 去重、1200ms 复检再调用 `ResetNetwork`。VPN 若短暂消失，还要 3 秒确认 + 5 秒退避重建。这部分是秒级，不是主因。

## 修复

- `AUTO` 的 `interval` 从 5m 改为 **1m**。
- 切网并 `ResetNetwork` 之后 800ms，主动对配置里所有 `urltest` 组发起一次 `URLTest`，立即重新选路，不再等周期。
- DNS 按分流方式拆分：大陆模式 `cn` 域名走 `dns-local`（系统解析，节点挂了也能解析国内站点），其余走 `dns-remote`；GFW 模式反过来，`gfw` 走远程、其余 `dns-local`。
- 新增两条诊断日志：`network change applied in Xms` 与 `urltest refresh requested for AUTO`，方便确认切网处理耗时。

## 验证范围

- 104 项相关 Node 检查通过（104 项执行），新增 1 项“切网触发 URLTest”回归检查。
- 官方 1.14.4 CLI 校验两种分流方式的运行配置通过。
- Release HAP 构建通过；**尚未安装真机验证**，实际切网恢复时间需要真机测量。

## 仍然存在的边界

- 如果所有节点在新网络下都不可用，仍要等测速失败后才会提示；这不是切网处理能消除的。
- 首次 DNS 解析在节点刚恢复时可能多一次往返。
