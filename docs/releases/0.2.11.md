# 0.2.11 本地测试版更新说明

本版优先处理后台运行可靠性、IPv6／WebRTC 流量路径，并将内核从 1.14.3 升级到官方正式版 1.14.4。保留原有名称、图标、界面风格、配置及节点选择持久化。未扩展基础配置、节点分享等后续功能。

## 后台与恢复

- 把系统 VPN 通道状态与 sing-box 核心状态分别检查。两次完整系统网络快照确认 VPN 消失后才重建；核心状态明确停止时才尝试恢复，节点不通或测速慢不会触发重启。
- 网络清单读取失败表示未知，不当作 VPN 消失。记录自有 VPN 网络 ID 和 TUN 地址，检测到其他 VPN 时不自动抢占；多个 VPN 同时可见时保守等待。
- 恢复采用 5／15／60 秒退避，120 秒窗口最多 3 次尝试，避免持续重启耗电。继续保留手动停止、SSID 排除和原手动节点选择的优先级。
- 返回前台不再因为一次状态读取失败清空页面或直接显示未运行。后台暂停刷新和自动测速，保留最后一份有界页面数据；完整运行快照仍只在前台频繁读取。
- 对超过 30 秒无心跳、配置标识匹配、系统连续确认已无 VPN 且没有手动停止命令的孤立会话，返回界面后使用原有停止确认和锁定更新流程恢复，不能仅凭心跳超时创建第二个 VPN。

限制：系统把整个 Extension 进程结束后，进程内代码无法在后台自行运行或承诺永不被杀。本版未伪装音频／定位保活、未申请无依据的特权。已完成正常清理的系统停止不等同于异常崩溃，不会无条件重新开 VPN。后台可靠性仍需目标手机长时间验证。

## IPv6、DNS 和 WebRTC

- 系统 VPN 继续接管 IPv4 与 IPv6。新增“允许 IPv6”设置；关闭时仍捕获 IPv6，再在 TUN 内优先拒绝，避免用不接管 IPv6 的方式关闭。
- 新增“WebRTC 防直连”，默认开启。在规则／全局模式识别 STUN 并交给当前代理出站，避免其落入普通直连兜底。直连模式、SSID 挂起和排除应用保持其明确的直连行为；该选项可能影响需要直连的通话，可以关闭。
- 有配置 DNS 服务器时，将捕获入站的 53 端口 DNS 交给核心 DNS，保留用户的服务器和分流规则；没有 DNS 的最简配置不强行注入虚构服务器。
- 原始 JSON 不重写，隐私适配只作用于运行配置；设置保存后，运行中的 VPN 按原有安全停止／重新连接流程应用。

限制：VPN 应用不能保证隐藏浏览器主动暴露的本地 host candidate／网卡地址，也不能保护明确绕过 VPN 的应用或挂起期间的直连流量。STUN 经代理需要节点支持相应 UDP；不支持时不会通过新增规则兜底直连。不能把按配置产生的国内直连出口一概称作泄漏。
